# Icon Rules

> Icons are supporting cues, not replacements for labels.

---

<!-- @section:rules -->

## Rules

- Primary and destructive actions use icon + text together.
- Avoid icon-only controls unless the surrounding UI makes the meaning obvious and accessible.
- Keep icon stroke, size, and alignment consistent within a surface.
- Use one icon library per project unless a documented exception exists.

---

<!-- @section:accessibility -->

## Accessibility

- Decorative icons should be hidden from assistive tech.
- Meaningful icons still need visible text or an accessible name.
- Do not rely on color alone to communicate icon meaning.

---

<!-- @section:quick-ref -->

## Quick Reference

| Do | Avoid |
| --- | --- |
| Icon + text buttons | Ambiguous icon-only controls |
| Consistent icon family | Mixed icon styles |
| Accessible labeling | Meaning conveyed only by color |
